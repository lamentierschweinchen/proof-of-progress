## Themes

### Hard fork: testnet → devnet → mainnet, in that order, each one rougher than the last

- Testnet ([#402](https://github.com/multiversx/mx-chain-testnet-config/pull/402)) is the most mature: real bootstrap peer IDs, real round-exclusion bounds, a tag marked "Latest." Devnet ([#166](https://github.com/multiversx/mx-chain-devnet-config/pull/166)) matches it structurally and also has a "Latest" tag. Mainnet ([#281](https://github.com/multiversx/mx-chain-mainnet-config/pull/281)) has the recovery-checkpoint hashes filled in but an `EndRound = 0 # TODO add here` and two un-swapped bootstrap peer IDs marked `# TODO update` — a genuinely incomplete draft, not just an unreviewed one. Reading the three side by side is the clearest evidence yet of the actual rollout sequence: get it working on testnet, copy the mechanism to devnet, then start mainnet's version last and slowest.
- The "`tags/` = ready" convention flagged in yesterday's digest has now produced two "Latest" releases (`T2.1.1.0`, `D2.1.2.1`) pointing at code whose own PRs are still open and, in testnet's case, carry a dismissed review. That gap between the release-page label and the PR's actual review state is now a two-day pattern, not a one-off.

### The old hardfork mechanism is being deleted while the new one is being deployed

- [#8026](https://github.com/multiversx/mx-chain-go/pull/8026) removes the `[Hardfork]` config block, the `update/` package, and the `/hardfork/trigger` endpoint from `mx-chain-go` outright. Every config-repo PR in this digest ([#402](https://github.com/multiversx/mx-chain-testnet-config/pull/402), [#166](https://github.com/multiversx/mx-chain-devnet-config/pull/166), [#281](https://github.com/multiversx/mx-chain-mainnet-config/pull/281)) still has a `[Hardfork] EnableTrigger = true` block sitting immediately after the newly-added `HardforkRoundExclusions`/`HardforkRecoveryCheckpoint` tables. None of these PRs have merged yet, so there's no live conflict today, but #8026 landing before the config PRs are updated to drop that block would break config parsing on whichever network merges next. Worth watching whether #8026 waits for the fork to complete or the config PRs get a follow-up commit stripping `[Hardfork]` to match.
