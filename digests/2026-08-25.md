## Themes

### `mx-chain-go`'s Supernova drain-window stack goes four deep and starts touching real correctness edges

[#7983](https://github.com/multiversx/mx-chain-go/pull/7983) is no longer a lightly-sketched draft. Two additions since yesterday stand out. First, a new `GasProcessingPolicy` type (`process/gasProcessingPolicy.go`): when a candidate header is a legacy (non-V3) header inside the Supernova drain window — the gap between the epoch flag activating and the round flag activating — the block's gas limit is forced onto the *previous* epoch's `MaxGasLimitPerBlockInEpoch` value rather than the new epoch's, with an explicit error guard for epoch zero (`"Supernova drain cannot use the previous epoch for epoch zero"`). That's a concrete answer to a question the drain-window rules raised but hadn't addressed before: legacy blocks produced during the transition gap don't get to claim whatever gas limit Supernova sets, they stay bound to the old one. Second, `update/sync/syncMiniBlocks.go` — the pending-mini-block syncer used for hard-fork and full-history recovery — gets a real concurrency fix: the completion channel (`chReceivedAll`) was unbuffered and could accept a stale signal from a previous request batch, so the wait loop now re-verifies that every requested hash actually arrived before declaring the sync done, and the send is now non-blocking. This reads as a genuine race-condition fix uncovered while working the drain-window code path, not just plumbing.

### A fourth PR stacks on top: epoch-start trigger gets finality-evidence retry logic

[#7984](https://github.com/multiversx/mx-chain-go/pull/7984), opened today by `ssd04` directly on `#7983`'s branch, adds a batch of new methods to the shard epoch-start `trigger` — `trackMissingFinalityEvidence`, `requestFinalityEvidence`, `retryPendingFinalityEvidence`, `parentCanSettle` — that track meta headers the trigger can't yet confirm are finalized and retry requesting evidence for them, with a per-epoch cleanup (`removePendingFinalityEvidenceForEpoch`). Still a draft with an empty PR template like its parent, but the pattern is consistent: the epoch-start trigger needs to tolerate headers whose finality can't be immediately proven during the transition window, the same shape of problem `#7983`'s drain-window checks are solving one layer down. Four PRs deep on `rc/supernova` now (`#7971` → `#7983` → `#7984`), all from the same two authors (`AdoAdoAdo`, `ssd04`), all still unreviewed.
