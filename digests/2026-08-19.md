## Themes

### The state-accesses and resync-recovery threads both land, cleanly, within a day of opening

Both feature pairs tracked across the last several digests merged today. The state-accesses fix shows a textbook review loop: `raduchis` flagged a specific mutation-safety issue on Aug 18 morning, `AdoAdoAdo` shipped the exact refactor he asked for by early afternoon, and both reviewers re-approved within the hour. The resync-recovery thread went further — it picked up two additional stacked PRs (`#7966`, `#7967`) for block-creation-time edge cases discovered during review, with the last one merging this morning. Read together, this is the fastest full merge-to-`feat/testnet-fixes` cycle this digest series has tracked for either thread.

### `mainnet-config` #259 breaks its eight-digest freeze, and the change traces straight back to yesterday's PR

The only commit to land on `#259` since Aug 11 is a small, specific config change that removes a now-unused delay parameter and adds a new "assumed peer persister count" field with a comment describing exactly the full-history-sync retrieval logic from `#7965`. This isn't routine housekeeping — it's the config-repo half of yesterday's protocol change actually shipping.

### A coordinated dependency-tag sweep feeds two downstream releases

Seven `mx-chain-*` Go module repos (core, crypto, logger, storage, communication, vm-common, scenario) all got fresh version tags within about 80 minutes this morning. `mx-chain-proxy-go` and `mx-chain-es-indexer-go` immediately consumed them — replacing dev pseudo-version pins in `go.mod`/`go.sum` with the real tags — and both cut new releases off the back of it. This reads as release-train hygiene: pinning to tagged versions rather than commit-pinned dev builds, likely in preparation for whatever the next `mx-chain-go` release cut turns out to be (its own `go.mod` wasn't touched in this window).

### API-layer hardening: request body size limits

`mx-chain-proxy-go` added a bounded-body-size middleware with tests — an unauthenticated caller can no longer send an arbitrarily large request body and have the proxy read all of it into memory before validation. Small, self-contained, and worth noting under the brief's advisory-signal rule even though it isn't branch-flagged as a hotfix.

### Stuck items: `#7951` alone now

With `#259` moving today, `#7951` "extra txs api logs" is the sole item still frozen — thirteen digests running. The standing recommendation is unchanged: a direct check-in would resolve it faster than continued daily re-verification.
