## Themes

### Wallet hardening in JS and Python

- [js-core #684](https://github.com/multiversx/mx-sdk-js-core/pull/684) restricts keystore KDF, cipher, key length and IV length, checks that a decrypted key matches the file's account, parses PEM files more strictly, validates mnemonic address indexes and signing input types, and adds `ErrBadKeystore`.
- [js-core #685](https://github.com/multiversx/mx-sdk-js-core/pull/685) updates dependencies. Per the [release notes](https://github.com/multiversx/mx-sdk-js-core/releases/tag/v16.1.0), `@multiversx/sdk-bls-wasm` 0.3.6 fixes a validator initialization hang on Node.js 18+, the `protobufjs` peer moves to ^7.6.5, optional `axios` to ^1.20.0, direct dependencies on `uuid` and `sdk-transaction-decoder` are dropped, and TypeScript declarations resolve through `out/index.d.ts`.
- **js-core upgrade note:** 16.1 requires both `address` and `bech32` in secret-key keystores. Older backups that relied on 16.0 to restore omitted leading zero bytes will fail to import.
- [mx-sdk-py v3.1.0](https://github.com/multiversx/mx-sdk-py/releases/tag/v3.1.0) ([#297](https://github.com/multiversx/mx-sdk-py/pull/297)) adds NFKD normalization for BIP-39 mnemonics, bounds keystore scrypt parameters, checks decrypted keys against file fields, parses PEM files strictly, uses constant-time comparisons for the keystore MAC and user secret keys, fixes BLS failure handling, and upgrades `cryptography` to 50.0.2. Upgrading is recommended by the release notes.
- **sdk-py upgrade notes:** mnemonics with unusual spaces or characters now derive different (standard) addresses, so funds could sit at the address an earlier version derived. Intel macOS now needs a source build of `cryptography`.
- The same sdk-py release includes [#298](https://github.com/multiversx/mx-sdk-py/pull/298) ("native auth impersonate fix").
