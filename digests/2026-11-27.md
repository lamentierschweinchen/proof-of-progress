## Themes

### Proxy transaction status

- [proxy #524](https://github.com/multiversx/mx-chain-proxy-go/pull/524) (+265, three files) changes the completion check for move-balance smart contract results. It now skips the notarization requirement for successful same-shard records that are either refunds, or move-balance on both sides with no log events. The code comment says these settle with the parent transaction and are never notarized. Pending and cross-shard refund cases are covered by tests. `master` is [ahead of v1.5.3](https://github.com/multiversx/mx-chain-proxy-go/compare/v1.5.3...master) with this change.

### Node import-DB work

- Draft [mx-chain-go #8046](https://github.com/multiversx/mx-chain-go/pull/8046) got a [review-fix commit](https://github.com/multiversx/mx-chain-go/commit/0df238e34) touching metablock processing and the peer accounts state used for import-DB snapshots, with tests. It targets `rc/cleanup-and-improvements`.

### sdk-core 16 adoption (outside the watchlist)

- [mx-sdk-js-native-auth-server #40](https://github.com/multiversx/mx-sdk-js-native-auth-server/pull/40) (open) widens the `sdk-core` peer to `^15.x || ^16.x`. Its description says the current peer blocks the coordinated upgrade of `mx-sdk-nestjs` and `mx-api-service`.
- [mx-sdk-nestjs #270](https://github.com/multiversx/mx-sdk-nestjs/pull/270) (open) moves to NestJS 12, `sdk-core` ^16.1.0 and `ioredis` 6, and addresses `npm audit` findings. The PR marks it as breaking, to be released as 8.0.0.

### Smaller activity (outside the watchlist)

- [mx-sdk-nestjs #269](https://github.com/multiversx/mx-sdk-nestjs/pull/269) (merged) caps the local cache TTL at the remaining Redis TTL, so a value read from Redis is no longer cached locally past the key's expiry.
- [mx-sdk-dapp-liquidity #36](https://github.com/multiversx/mx-sdk-dapp-liquidity/pull/36) merged v2.4.3 to `main`: tokens are matched by chain ID as well as address.
- [mx-chain-notifier-go #153](https://github.com/multiversx/mx-chain-notifier-go/pull/153) (RabbitMQ max payload size, open) and [mx-multi-factor-auth-go-service #169](https://github.com/multiversx/mx-multi-factor-auth-go-service/pull/169) (concurrent register handling, open) were updated.
