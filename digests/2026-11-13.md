The node-side trie pagination work from yesterday now has a consumer: [mx-api-service #1663](https://github.com/multiversx/mx-api-service/pull/1663) (`stefangutica`, opened Nov 13) pages gateway trie endpoints using an `iteratorState` checkpoint, because the new node limits no longer return a whole trie in one response. Per the PR body: with the new gateway limits, trie endpoints no longer return the whole trie; large tries previously failed with `trie collection limit exceeded` / `trie operations timeout`, and now answer in pages resumed via `iteratorState`. The API read only the first page, so token lists of large accounts and the fungible token list came back incomplete. ## Themes

### Trie pagination across node and API layers

- [mx-chain-go #8060](https://github.com/multiversx/mx-chain-go/pull/8060) (node, open) and [mx-api-service #1663](https://github.com/multiversx/mx-api-service/pull/1663) (API consumer, open) are two halves of one change: bounded, resumable trie walks. The API PR documents the failure modes being removed (`trie collection limit exceeded`, `trie operations timeout`) and the user-visible symptom if the API ignored paging (incomplete token lists for large accounts).

### Indexer data pipeline

- [es-indexer #390](https://github.com/multiversx/mx-chain-es-indexer-go/pull/390) introduces a RabbitMQ blocks exchange with config and request-layer changes; large and labeled "Initial implementation". [#389](https://github.com/multiversx/mx-chain-es-indexer-go/pull/389) (token metadata and ESDT property fixes) remains open.

### Contract framework / Rust SDK

- [mx-sdk-rs #2442](https://github.com/multiversx/mx-sdk-rs/pull/2442) begins typed models for MultiversX API responses (accounts, transactions, events, upgrades) in `sdk/core`, following the interactor gas work in [#2441](https://github.com/multiversx/mx-sdk-rs/pull/2441).
