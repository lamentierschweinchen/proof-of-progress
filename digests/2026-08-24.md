## Themes

### `mx-chain-go` starts building the actual drain-window logic for the Supernova cutover

[#7983](https://github.com/multiversx/mx-chain-go/pull/7983) does two things. First, it refines `checkLegacyPredecessorReadyForV3`: previously *any* non-final mini-block left in the last legacy block hard-blocked the V3 transition outright. Now it separately checks the `processedMiniBlocksTracker` for genuinely unfinished work (`HasUnfinishedMiniBlocks`, a new method added to the tracker interface and its disabled stub) — a legacy block can still carry mini-blocks that are non-final purely because they're mid-continuation, and those no longer block the switch. Second, and new: `checkSupernovaDrainRules` runs specifically in the window between the epoch flag activating and the round flag activating (`IsInSupernovaDrainWindowForEpochAndRound`) — it rejects any newly-scheduled mini-block outright (`ErrScheduledMiniBlockInSupernovaDrain`) and rejects any mini-block claiming `PartialExecuted` state unless the tracker can prove it's an existing, already-started continuation (`ErrNewPartialMiniBlockInSupernovaDrain` otherwise). This is the first commit in the series that reads as actual cutover-day mechanics rather than a clock constant. It's a draft with an empty PR template (no description filled in) stacked three deep on `rc/supernova`-bound branches, so treat it as early and unreviewed — but it's the clearest signal yet that engineering is now working the literal mainnet-transition edge cases.
