## Since the last digest

- **`mx-api-service` [#1632](https://github.com/multiversx/mx-api-service/pull/1632) "handle token creation event" merged 14:36:38Z Sep 8** (`stefangutica`, 4 files, +201/−83). Newly issued tokens previously only became visible in the API after the ESDT-token-list cache warmer rebuilt its full list (every 2 minutes). This PR extracts per-token enrichment out of `getAllTokensRaw` into reusable helpers, adds a single-token `TokenService.getTokenRaw(identifier)` path, and wires the transaction processor to detect `issue` transactions to the ESDT system contract, fetch the new token once its `ESDTTransfer` callback confirms, and splice it into the cached list with a pubsub invalidation — cutting the visibility delay from "up to 2 minutes" to near-immediate. Third caching/performance PR from the same author in three calendar days, following #1628 (batched Redis lookups) and #1631 (gateway response-size cap), both already covered in the Sep 8 digest.
